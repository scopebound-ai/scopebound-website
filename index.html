The problem

Your agents have no enforcement layer

Every major framework ships with zero enforcement between the LLM's decision and the tool's execution. When an agent decides to call a tool, nothing checks whether it's allowed.

🚫

No tool-call enforcement

The LLM decides to call delete_invoice. The tool runs. Nothing between the decision and the execution checked whether that was allowed.

🔄

Runaway agents

A reconciliation bug triggers 3,000 consecutive writes in 45 seconds. No rate limit. No session revocation. 3,000 records corrupted before anyone notices.

🔗

Permission inheritance

A sub-agent three hops down the chain writes unvalidated data to production. The parent's permissions have no boundaries between agents.

How it works

Enforcement inside the execution loop

Scopebound sits between the LLM's decision and the tool's execution — the only point where enforcement is both reliable and sub-millisecond.

01

Provision a session

At job start, call /v1/provision with the role name. Get back a scoped JWT — role, allowed tools, rate limits, TTL, and constraints baked in.

02

Scopebound intercepts (<5ms)

Before every tool call, POST to /v1/enforce. The policy engine checks the JWT against the tool name and call arguments in under 5ms.

03

Allow or deny

If allow → proceed. If deny → block. The tool never executes on a deny. Every decision written to a tamper-evident audit log.

04

Audit everything

SHA-256 hash chain across every event. Every allow and deny. Chain violation halts the server. SOX-ready out of the box.

Integration

Three lines of code

Add enforcement to any existing agent tool. Nothing else in your codebase changes.

from scopebound import ScopeboundClient
from langchain.tools import BaseTool

sb = ScopeboundClient(base_url="https://your-partner.api.scopebound.ai")

# Wrap your existing tool — nothing else changes
@sb.enforce(role_id="invoice-processor")
class ReadInvoicesTool(BaseTool):
    name = "read_invoices"
    description = "Read pending invoices"

    def _run(self, status: str = "pending") -> str:
        return get_invoices(status)

Features

Everything you need to secure agents in production

⚡

Sub-5ms enforcement

Policy evaluation adds under 5ms per tool call. p99 under 10ms in production. OPA evaluator pre-warmed at startup — no cold-start penalty.

🔑

Cryptographic agent identity

Every agent session gets a scoped JWT. Role, allowed tools, rate limits, TTL, parameter constraints, and time windows baked into the token.

📋

Tamper-evident audit trail

Append-only log with SHA-256 hash chain. Every allow and deny recorded. Chain violation halts the server. SOX-ready out of the box.

🎯

Tool parameter constraints New

Enforce field-level rules on tool arguments. Not just which tools — but how they're called. Six operators: eq, lt, gt, contains, regex, in.

🌍

Environment enforcement New

Scope agent sessions to specific environments. A staging agent cannot call production tools. Pass env in call_args and the policy engine verifies it.

🕐

Time-based access controls New

Restrict when agents can operate — by UTC hour window and day of week. A 3am call is a signal. Now it's also a deny.

🧬

Role inheritance New

Child roles inherit parent tools additively. Define a base role once — specialist roles extend it. Maximum depth: 2. Child can only add, never remove.

📦

Policy versioning & rollback New

Upload new policy bundles via the management API with instant hot-reload. Roll back to any of the last 10 versions in one API call. No restart required.

📊

Behavioral drift detection

Statistical baseline + Isolation Forest. Anomaly score above threshold triggers automatic session revocation. Catches what rate limits miss.

🚦

Per-role rate limiting

Token bucket limits per session — per minute and per hour. Two independent layers of blast-radius control. Exceeded calls denied before execution.

🔔

Real-time deny webhooks

HMAC-signed webhook on every deny. SCOPE_VIOLATION, PARAMETER_VIOLATION, TIME_VIOLATION, ENV_VIOLATION, RATE_LIMIT_EXCEEDED, BEHAVIORAL_DRIFT. Your ops team knows instantly.

🔌

Framework-native + MCP

Adapters for LangChain, OpenAI Assistants, CrewAI, AutoGen, Semantic Kernel, Claude Agent SDK, and MCP. Proprietary layer? Use the HTTP API — ~20 lines.

📈

Analytics & partner dashboard

Postgres-backed analytics — total calls, allow/deny rates, top denied tools, MCP vs framework split, calls by hour. Live dashboard included.

🔒

Dedicated HTTPS enforcement plane

Each partner gets a dedicated instance at partner.api.scopebound.ai with TLS, isolated Postgres schema, and automatic cert renewal.
